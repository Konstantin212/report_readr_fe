- **Open Self-Service Sign-Up — sign-up modes, email verification, password reset & rate limiting** — OAuth (Google/GitHub) and a new email+password sign-up/sign-in path; `AUTH_SIGNUP_MODE` makes the pre-existing admin-approval allowlist gate opt-in (`restricted`) rather than the default (`open`); Resend-backed email verification and password reset (revokes other sessions on reset); better-auth's built-in rate limiting turned on. **Note:** this doc's original email-verification behavior (sent unconditionally, nudge-only — does not block sign-in) was superseded 2026-08-06 — see the entry below for current (blocking) behavior. → [AC](superpowers/specs/2026-08-05-open-signup-ac.md) / [design](superpowers/specs/2026-08-05-open-signup-design.md)
- **Email Verification Gate + Live Cross-Tab/Cross-Device Auto-Login** — Email verification is now mandatory and blocking: sign-in on an unverified email+password account hard-rejects instead of nudging, and route access under `(app)` also checks `emailVerified`. Adds a live, no-manual-refresh transition into the app once the verification link is opened — same-browser tabs sync via `BroadcastChannel`, a different device/browser gets a rate-limited, opaque-attempt-id polling grant — plus anti-enumeration on duplicate sign-up and on invalid/expired verification links. Supersedes the nudge-only email-verification behavior described in the entry above. → [AC](superpowers/specs/2026-08-06-email-verification-gate-ac.md) / [design](superpowers/specs/2026-08-06-email-verification-gate-design.md)

## Instrumentation & Analytics
- **Vercel Web Analytics — Custom Event Tracking** — 24 narrowly-typed `track*` functions in `src/lib/analytics-events.ts` (single boundary module — the only file that imports `track` from `@vercel/analytics`; no generic `track(name, props)` escape hatch), wired at ~20 call sites across Upload, Auth, Tax, Positions/Dashboard, Settings, and Nav/Onboarding. `<Analytics />` mounted once in root layout so every route (including sign-in/verify-email/reset-password) is covered. GDPR: each event's allow-list is enforced structurally by its function signature — never amounts, emails, account numbers, or holdings-identifying symbols/ISINs; fails open (try/catch) so a blocked/failed analytics call never breaks app functionality. Implemented and reviewed; see [changelog](CHANGELOG.md). → [AC](superpowers/specs/2026-08-07-analytics-events-ac.md) / [design](superpowers/specs/2026-08-07-analytics-events-design.md)
